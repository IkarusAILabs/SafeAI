# Authority Evidence Validation — validation report (v2.6, hardened)

> Research hub: [ikaruslabs.net](https://ikaruslabs.net) | SafeAI: [ikaruslabs.net/safeai](https://ikaruslabs.net/safeai)

Status: measured evidence. Machine record: `evaluation.json`; reviewer
brief: `brief.md`. Both generated by `safeai benchmark
--no-determinism` (the committed records carry
`determinism.checked: false` per case). The default path adds repeat +
order-shuffle determinism checks on every case and is what CI runs.

Reproduce the committed records byte-for-byte:
`python -m safeai.cmd.cli benchmark --no-determinism --json
evaluation.json --markdown brief.md` from the repo root (offline, no
network, no execution of scanned code). Exit 0 means every case holds;
exit 1 names the mismatched cases; exit 2 is a harness error (never a
measurement).

Since v2.7.0 CI (`authority-benchmark` job in `.github/workflows/ci.yml`,
Python 3.11–3.13) runs the full corpus with determinism checks on every
pull request and push to `main`, and fails if any case stops holding.

This is a research artifact about SafeAI ("how well SafeAI performs
on a fixed corpus"). It never belongs inside a customer scan report
("your project"): customer reports contain no benchmark numbers
(enforced by `test_customer_reports_contain_no_benchmark_numbers`).

## Offline HTML presentation

Generate an HTML view from an existing `evaluation.json` without running
the scanner or recalculating metrics. From the repository root, run this
Python snippet (standard library only; no new dependencies):

```python
import json
from pathlib import Path
from safeai.benchmark.report import write_html

source = Path("docs/benchmarks/authority/evaluation.json")
evaluation = json.loads(source.read_text(encoding="utf-8"))
write_html(evaluation, "authority-benchmark.html")
```

Open `authority-benchmark.html` in a browser. It is self-contained and
works offline, with no scripts, remote fonts, or other network assets.
Keep generated HTML local; it does not need to be committed.

The page presents all eight attribution levels, per-class Lane-A
verdicts, and ChangeGuard rates in tables, with redundant bars on a 0–1
scale. Text retains the exact numbers and qualifications from
`render_markdown(evaluation)`; no percentages are rounded or verdicts
reclassified. Missing values and insufficient evidence have no bar;
measured zero remains `0.0`. Known limitations and the existing `Watch`
categories are highlighted. Tables scroll on narrow screens and remain
readable without color or animation. The expandable **Markdown source**
contains the complete current brief, recoverable byte-for-byte as UTF-8
after HTML entity decoding.

For trends, load historical committed evaluations exported to local
JSON files, and supply revision labels in the order to display:

```python
# These files must already exist; choose revisions whose artifacts you
# want to review. No Git lookup, download, or automatic sorting occurs.
history = [
    ("older-revision", json.loads(Path("older-evaluation.json").read_text(encoding="utf-8"))),
    ("newer-revision", json.loads(Path("newer-evaluation.json").read_text(encoding="utf-8"))),
]
write_html(evaluation, "authority-benchmark.html",
           history=history, label="current-revision")
```

Supply at most 20 historical evaluations per HTML report. A larger history
raises `ValueError` before rendering or opening the output file; an existing
report remains unchanged. Select a smaller history explicitly rather than
relying on silent truncation. This bounds the number of embedded historical
briefs, not the size of an individual evaluation.

The current evaluation is appended after the supplied history. The trend
table shows revision labels, corpus case counts, Lane-A status,
end-to-end exercised authority attribution coverage (including matched
and expected counts), observed false-escalation rates, and missed-material
rates. Each historical brief is available in an expandable section with
its full qualifications and limitations. With no history, only the
current brief is shown; one historical artifact is sufficient to enable
the trend view. Repeated inputs and ordering produce identical UTF-8 HTML
bytes with LF newlines on every platform.

These are observations on each artifact's corpus, not an improvement
score. Corpus mix, annotations, or truth can change between revisions;
case counts alone do not establish comparability. A rising coverage bar
does not prove scanner improvement, and zero observed false escalations
does not establish universal safety. The original UNKNOWN vetoes,
PROPOSED targets, and surface-blind-change qualifications remain visible
in the briefs. Metric calculation and comparison are unchanged.

## Methodology (what the numbers prove)

- 56 cases pair minimal agent/IaC inputs with hand-verified,
  implementation-independent canonical gold truth
  (`truth_schema_version: "2.0"`, `annotation: {basis:
  human_reviewed_source, confidence}`): human agents, tools,
  capabilities, identities, grants, relationships, authority
  statements, expected material changes, unknown expectations. Gold
  never encodes scanner internals (`unknown:unattributed` appears in
  no gold file — verified by test).
- The harness projects scan output into the same canonical shape and
  compares by neutral keys (names, kinds, namespaces, slugs), never by
  `tool_key` strings.
- Entity discovery, 8 attribution levels, material-change/escalation
  PRF, unknown preservation, evidence completeness, and determinism
  are measured independently. A missing gold section reports
  `insufficient_evidence`, never 0/1; rates with empty denominators
  do the same (a system predicting nothing has proven nothing).
- Baseline pairs assert an expected materiality per entry
  (`NO_CHANGE … AUTHORITY_ESCALATION … UNKNOWN_CHANGE`) plus whether
  the surface should show it (`surface_expected`). Entries outside
  the surface model are counted blind spots (3), with detection still
  enforced via findings/summary channels — explicit per-entry gold,
  not a hidden hatch.
- Lane-A verdicts are per-class (capability detection, identity
  attribution, authority attribution, change detection, escalation
  detection) against PROPOSED bars (ADR-0008; no gate consumes them).
  Authority attribution gates on the end-to-end rate over ALL
  exercised capabilities including the unattributed bucket. Any
  observed unknown/unresolved evidence vetoes overall readiness.

Capability detection and identity attribution read LANE-A CANDIDATE
(coverage 1.0) on corpus evidence. Authority attribution reads
LANE-B (0.4851 < 0.95), change detection LANE-B (model coverage

## Blind spots documented (not hidden)

1. Code-defined tools land in `unknown:unattributed` (69/134 caps).
   Findings still fire; the surface cannot name the tool.
2. `agent_uses_tool` edges are beyond the current model (5 gold edges
   `resolvable: false`, relationship coverage 0.9451; excluded from
   P/R denominators — never scored as correct).
3. Surface-blind material entries: 3 (legacy code-tool baseline
   pairs); detection via findings/summary enforced instead.
4. Repo-scoped (not tool-scoped) identity links yield UNKNOWN
   verdicts even with resolved grants (multiple_identities,
   attachment_chain pattern).
5. Change/escalation denominators are small (5/4): CANDIDATE reads
   carry visible TP counts, not large-sample confidence.
6. Sensitivity is proven, not assumed: 8-area live-logic mutation
   tests (identity, namespace, wildcard, grant, capability
   attribution, correlation, change classification, UNKNOWN
   downgrade) plus a live input-neutering test all require failure.
